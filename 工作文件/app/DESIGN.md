# 自媒体通关搭档 Web 开发版 v0.2 设计说明

## 产品定位

当前界面是用于持续打磨功能的单任务 Web 工作台，不是营销落地页，也不是本轮甲方交付定稿。核心体验是：先让用户看到一版可执行的内容研究稿，再向下展开拍摄细节、证据来源和发布阻塞项。

设计原则：结果优先、证据可追溯、状态不夸大、操作路径短、专业信息可扫描。

## 设计参数

- `DESIGN_VARIANCE: 3`
- `MOTION_INTENSITY: 2`
- `VISUAL_DENSITY: 6`
- 浅色、低动效、中等信息密度。
- 控件圆角 6px，结果面板最大 8px。
- 字距固定为 0，不使用随视口缩放的字号。
- 系统无衬线字体，不依赖外部字体资源。

## 信息架构

### 输入工作带

首屏直接提供实际工作入口，不使用营销 Hero：

1. 公开视频链接。
2. 可选字幕或口播稿。
3. 可选音视频上传与转写。
4. 可选商品事实。
5. ASR 策略选择。
6. 预留但禁用的目标地区/国家入口。

链接输入和“开始分析”是唯一主操作。补充资料收在可展开区域，避免首次使用时形成长表单压力。

### 结果三层结构

结果区按用户的决策顺序组织：

1. **唯一推荐成稿**：先展示交付状态、完整脚本与发布内容包。默认只有一版主稿，不把多个候选稿交给用户拼接。
2. **拍摄执行表**：以稳定表格展示时间、画面、口播、字幕、商品证明与声音，直接服务拍摄和剪辑。
3. **证据、判断与风险**：展示来源完整度、ASR 状态、内容蒸馏、地区本地化状态、商品事实门禁和风险审核。

专业信息放在第三层，不与主稿争夺第一视觉焦点；但发布状态始终在报告标题旁可见，不能被折叠隐藏。

## 发布状态设计

界面必须明确区分：

- `research_draft`：研究稿，禁止直接发布。
- `publish_ready`：只有后端证据门禁明确允许时才显示可发布。
- `needs_input`：需要字幕、媒体或商品资料。
- `partial`：已有部分结果，但证据仍不完整。
- `unsupported`：链接平台当前不支持。

`publishable=false` 时：

- 标题旁显示“研究稿 · 禁止直接发布”。
- 主按钮文案使用“复制研究稿”，不能写成“导出发布稿”。
- 商品事实、证据或人工审核缺失项必须保留在结果中。
- DeepSeek 或其他模型生成成功不能改变发布门禁。

## 平台与证据表达

- 抖音和 TikTok 显示为当前可识别平台。
- 登记样本必须说明其来源是本地经审阅 fixture，不冒充本次实时抓取。
- TikTok 提交链接只能证明“用户提交了该 URL”以及可从 URL 解析出的标识，不能自动证明页面内容已经取得。
- YouTube、Facebook 和 X 只显示后续计划，不使用“即将可用”等确定承诺。
- 事实、推断、用户提交资料和待确认项使用不同标签与语义色。

## ASR 交互

当前策略控件提供：

- 自动选择。
- 外部 API 优先。
- 本地优先。

界面必须展示实际 provider 的配置和执行状态，不能只显示用户选择值。当前 Web 表单已实现文件选择、25 MB 即时校验、转写中状态、失败提示和字幕框回填；转写完成后不会自动分析，用户可以先修订文字，再显式点击主按钮。

仍需后续完善：

- 可计算的上传进度、取消与失败重试。
- 媒体发送到第三方服务前的独立确认和隐私说明。
- 分段、时间码、置信度与原媒体对照预览。
- provider 专用配置与成本提示。

## 地区与国家交互

v0.2 保留目标地区/国家选择器的位置和字段语义，但控件保持禁用，并显示“本版本未启用”。后端可以记录 `region`、`country`、`language` 请求值，但必须返回：

- `enabled=false`
- `applied=false`
- `status=future_disabled`

在本地化规则、语言质量和市场事实未验真前，不得因用户选择地区自动添加俚语、文化结论、价格、法规或平台趋势。

## 视觉系统

- 画布：`#f7f8f6`
- 表面：`#ffffff`
- 正文：`#18201d`
- 弱化文字：`#66716c`
- 细线：`#d9dedb`
- 强调色：`#087f5b`
- 深强调色：`#066649`
- 警告色：`#9a6700`
- 风险色：`#b42318`

强调色用于主操作和已确认状态；警告与风险色分别表达待核验和发布阻塞。页面不使用装饰性渐变球、玻璃拟态卡片、过量仪表盘组件或大面积单一深色主题。

## 布局与响应式

- 顶部产品栏保持紧凑，不承担营销导航。
- 输入区为全宽工作带，内部内容受容器宽度约束。
- 报告区纵向排列三层结果，不做卡片嵌套。
- 第三层在宽屏采用证据侧栏与专业报告双列；窄屏改为单列。
- 拍摄表使用稳定列宽和横向滚动容器，动态文字不能改变整体布局。
- 移动端按钮与输入控件最小高度 44px，长标题和状态文案允许换行。
- 页面需保持键盘可达、清晰焦点、`aria-live` 状态提示和错误就地展示。

## 状态与反馈

- 空状态：显示输入工作带，不用功能介绍卡片填满页面。
- 加载中：使用与结果结构对应的稳定加载状态，避免布局跳动。
- 需要补充资料：列出缺失字段并聚焦对应输入。
- 部分结果：展示研究稿，同时保留证据缺口和发布阻塞。
- 完整登记样本：展示三层报告，并说明样本性质。
- 错误：在表单和结果区提供持久错误信息，不只使用瞬时 Toast。
- 复制：明确区分“复制研究稿”和“复制完整脚本”，复制反馈需可被辅助技术读取。

## 文案边界

- 不承诺爆款、流量保证、平台审核通过或法律合规。
- 不把模型生成写成事实核验。
- 不在客户界面暴露 API Key、内部提示词或服务端实现细节。
- DeepSeek 仅作为内容生成 provider；ASR provider 必须按实际执行结果单独展示。
- “完整”“已接通”“可发布”等词只能由真实证据和后端状态支持。

## 当前非目标

- 本轮不重建或更新甲方交付包。
- 不做账号体系、计费、多租户或自动发布。
- 不读取 Cookie、密码、本地存储或浏览器个人登录态。
- 不宣称阿里云百炼、AssemblyAI、DeepSeek 或本地 Whisper 已完成真实凭据验收。
- 不在 v0.2 启用地区本地化内容生成。
