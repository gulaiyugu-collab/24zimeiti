# 架构设计 v0.1

## 总体结构

```text
轻量 Web 页面
  -> API
       -> 采集任务存储
       -> 隔离 Worker -> 平台适配器 -> 原始证据
       -> 精简证据清单
  -> 编排 Agent
       -> 按需读取精简证据
       -> 内容蒸馏
       -> 原创内容生成
       -> 平台/行业风险检查
       -> 报告导出
  -> 项目数据存储
```

## 平台适配器契约

每个平台适配器统一输出：

```json
{
  "platform": "douyin",
  "url": "https://...",
  "author": {},
  "content": {},
  "metrics": {},
  "comments": [],
  "evidence": [],
  "missing": [],
  "acquisition_mode": "public_page|transcript_fallback|fixture"
}
```

第一版实现 `douyin`。后续增加 `youtube`、`facebook`、`x` 时只实现同一契约，不修改蒸馏和生成层。

## 抖音采集策略

1. 优先读取公开详情页可见字段。
2. 能取得章节/字幕时记录来源与时间戳。
3. 只能取得标题和指标时降级为低完整度，不生成伪完整结论。
4. 页面受登录墙、验证码或签名限制时停止重试，要求用户补充分享文案或字幕。
5. 不导出 Cookie，不要求客户提供账号密码。

## 行业风险发布前审核

保健品内容在生成后必须检查：

- 疾病诊断、治疗、根治和药品替代暗示。
- 未提供证据的功效、专利、认证和权威背书。
- 绝对化、保证结果、无副作用等表述。
- 特殊人群、适宜/不适宜人群和使用方式缺失。
- 普通食品、保健食品和药品身份混淆。

命中高风险时仍可生成研究稿，但不能标记为“可发布”。

## 云端部署边界

- Web、Agent 和内部 Skill 部署在服务端。
- 平台采集使用隔离 Worker，主应用不持有浏览器个人登录态。
- 模型密钥只存服务端密钥管理，不写入仓库或报告。
- 第一阶段不做账号体系、计费和多租户，只保留接口边界。
- 所有异步任务只有在 `completed` 后才可展示完整报告。

## 采集上下文隔离

v0.2.1 增加单机隔离 Worker MVP，目标是让网页解析、下载、转写、OCR、重试和原始日志不占用编排 Agent 的默认上下文。

```text
POST /api/acquisition/jobs
  -> request.json + status.json
  -> 独立 Python 子进程
  -> raw/source.json
  -> evidence_manifest.json
  -> Agent 默认只读取 manifest
```

约束：

1. API 主请求只返回 `job_id`、状态、进度、缺失项和清单地址。
2. Worker 标准输出与错误写入任务目录，不拼入 API 响应。
3. 原始证据保存在 `raw/`；默认清单限制条目数量和文字长度，并通过文件哈希关联原始证据。
4. 原始证据只能使用任务状态中登记的白名单文件名读取，阻止路径穿越和任意文件读取。
5. 缓存键由规范化链接、条目数量和采集契约版本生成；只有 `completed` 结果可复用。
6. `needs_input`、`failed`、`queued` 和 `processing` 不得进入完整分析或冒充采集完成。

Codex 执行入口使用 `python -m app.acquisition_cli`。该入口内部提交并轮询任务，只在终态打印一条精简 JSON；因此编排对话不需要接收每一步浏览器、下载、转写和 OCR 日志。

当前 Worker 已真实完成登记样本整理、未知链接证据检查、状态持久化、缓存和精简清单生成。实时抖音/TikTok 页面抓取、主页多作品采集、媒体下载、评论采集和自动转写仍未接入，不能据此宣称实时采集已完成。正式多实例部署还需外部队列、Worker 并发上限、超时终止、任务保留期和清理策略。
