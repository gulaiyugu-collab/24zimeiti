## 1. 系统定位与总体架构

项目024 是一个运行在 Windows 本机的 Web 应用。用户在浏览器中提交一条公开的抖音或 TikTok 单作品链接，系统完成媒体采集、字幕提取或本地转写、结构化内容研究稿生成，并保留证据链与发布前审核边界。

总体架构分为四层：

```
┌─────────────────────────────────────────────────────┐
│  前端层  static/index.html + app.js（主工作台）        │
│          static/publish.html + publish.js（发布校准） │
├─────────────────────────────────────────────────────┤
│  API 层  FastAPI 单进程（app/main.py）                │
│          监听 127.0.0.1:8792（演示）/ 8787（开发）     │
├─────────────────────────────────────────────────────┤
│  服务层  acquisition（任务状态机+缓存）                │
│          douyin_media / tiktok_media（采集通道）       │
│          asr（转写路由） content_generation（LLM）     │
│          product_relevance（商品分流）                 │
│          visual_analysis（代表帧+候选镜头结构）         │
│          publish_calibration（校准闭环）               │
├─────────────────────────────────────────────────────┤
│  执行层  独立 Python 子进程 Worker（隔离采集+本地 ASR） │
│          Node.js playwright-core（抖音浏览器回退探测）  │
│  存储层  文件系统：var/acquisition/{job}/              │
│          SQLite：var/publish_calibration/calibration.sqlite3 │
└─────────────────────────────────────────────────────┘
```

关键设计决策：

- **主进程不执行采集**。`POST /api/acquisition/jobs` 只负责入队并返回 `job_id`，实际来源检查、媒体下载和转写在独立子进程中执行，Worker 的 stdout/stderr 不会进入默认分析响应，避免原始日志和中间数据泄漏到甲方可见链路。
- **单机单实例**。当前是单机子进程 Worker MVP，服务只监听回环地址；正式多实例部署需要外部队列、并发限制、超时终止与任务清理策略（Dockerfile 已具备基础镜像，但生产配套未完成）。
- **状态即文件**。每个任务的 `request.json`、`status.json`、`evidence_manifest.json` 与 `raw/` 目录全部落盘，主进程重启后任务状态可恢复。

## 3. 主链路流程：从链接到研究稿

主路径完全由前端驱动，用户不需要手动粘贴字幕：

```
提交链接
  │ POST /api/acquisition/jobs  {url, item_limit, force_refresh}
  ▼
主进程入队 → 启动隔离 Worker 子进程
  │ 状态机: queued → processing → completed | needs_input | failed
  ▼
Worker 内部:
  1. 平台适配器识别 (douyin/tiktok) + URL 规范化 + 作品号提取
  2a. TikTok: 代理预检(只检测不修改) → yt-dlp 元数据 → 平台字幕优先
      无字幕 → 下载音轨 → 本地 faster-whisper 转写
  2b. 抖音: 公共 Provider 取元数据与媒体
      Provider 失效 → 隔离浏览器回退(无登录态 Chromium/Chrome)
      分离音视频流 → 按 media-video/media-audio + Content-Range 选完整候选并合并
  3. 媒体流强制校验(必须同时含视频流与音频流才进 ASR)
  4. 本地 GPU 转写: large-v3-turbo, cuda/int8_float16, 带时间码分段
  5. 生成精简证据清单 evidence_manifest.json(白名单字段+SHA-256)
  6. status.json 落盘; completed 任务写入缓存
  ▼
前端轮询 GET /api/acquisition/jobs/{job_id} 至终态
  ▼
POST /api/acquisition/jobs/{job_id}/analyze  {analysis_mode, product_context}
  │ 校验: 拒绝非 completed / 空字幕 / 无字幕哈希 / 客户端 transcript 覆盖
  ▼
已登记视频 → 本机代表帧与候选镜头结构（OCR 未安装时明确 unavailable）
  ▼
精简清单 + Worker 字幕 + 公开指标 + 收敛后的画面结构证据 → DeepSeek
  ▼
结构化报告: 一句话结论 / 内容结构 / 有效原因 / 可借鉴方法
            完整脚本 / 拍摄表 / 发布内容包 / 发布前审核
```

三种降级入口在主路径失败后仍可用：手动粘贴字幕（`POST /api/analyze` 带 `transcript`，产出 `partial` 研究稿）、受限媒体上传转写（`POST /api/transcribe`，25 MB 上限）、登记样本 fixture（本地审阅报告，明确标注 `registered_fixture` 来源）。

## 4. 模块设计与交互

### 4.1 平台适配器（app/adapters/）

`douyin.py` 与 `tiktok.py` 提供平台无关的入口函数：`detect_platform()`（URL → 平台判定）、`canonical_url()`（规范化链接，去除查询参数，作为缓存键）、`extract_aweme_id()` / `extract_tiktok_video_id()`（提取稳定作品号）。短链过期时，系统可从本机已登记的公开元数据中恢复作品号，避免重复失败。YouTube/Facebook/X 已定义适配器契约，状态为 `planned`。

### 4.2 采集任务管理（app/services/acquisition.py）

- 任务 ID 格式 `acq_YYYYMMDDTHHMMSSZ_<12位hex>`，带正则校验；产物文件名白名单 `[A-Za-z0-9._-]{1,120}`。
- 状态机：`queued → processing → completed | needs_input | failed`。只有 `completed` 进入缓存；`needs_input`（如代理不可用）绝不伪装成已采集内容。
- 缓存键：规范化链接 + 请求参数。同一来源二次提交命中同一任务（`cache_hit=true`）；`force_refresh` 可强制重采。
- 所有 JSON 落盘使用原子写（临时文件 + `os.replace`），避免半写状态。

### 4.3 采集通道（douyin_media / tiktok_media）

抖音采用双通道：公共 Provider 优先，失败后自动切换隔离浏览器。隔离浏览器通过 `douyin_browser_probe.cjs`（Node.js）驱动 playwright-core 启动无个人登录态的临时上下文，按响应类型区分 `media-video` 与 `media-audio` 流，用 `Content-Range` 总长度选取完整候选后合并。临时签名媒体地址只存在于 Worker 内存，不写入元数据、清单或日志。单文件下载安全上限 512 MiB（超限明确报错，防异常链接耗尽磁盘）；视频时长不设应用层上限。

TikTok 通道在 Worker 内先做代理预检：程序只检测和使用系统代理，不启动、修改或读取代理客户端私有配置。代理不可用返回 `needs_input` 并提示开启 VPN，不进入缓存。

### 4.4 转写路由（app/services/asr.py）

`ASRRouter` 的 `auto` 策略为"外部 API → 本地"的可用性顺序单选（不是失败重试链）。自动采集 Worker 固定使用本地 ASR，不产生付费调用。本地 ASR 关键参数（均可用环境变量覆盖）：模型 `large-v3-turbo`、设备 `cuda`、计算类型 `int8_float16`（CPU 回退 `int8`）、可配置是否允许 CPU 回退（`PROJECT024_LOCAL_ASR_ALLOW_CPU_FALLBACK=0` 用于严格 GPU 验收）。模型缓存固定在项目 G 盘目录。

### 4.5 画面结构分析（app/services/visual_analysis.py）

主进程只从采集清单选择 `role=source_media` 且 `content_type=video/*` 的白名单文件，核对实际文件大小与 SHA-256 后调用本机 `ffprobe/ffmpeg`；HTTP 请求不能提交本机路径。分析覆盖前 1200 秒，以 5fps 的 scene score 产生候选切点、合并 0.75 秒内的近邻，再用场景点与均匀覆盖组合提取最多 12 张、宽度不超过 720px 的 JPEG。结果中的“快/中/慢”仅为启发式节奏，不能证明画面对象、动作或文字；本机没有 OCR 引擎时返回 `ocr.status=unavailable`。

单媒体上限 512 MiB，外部命令共享 90 秒总截止时间；报告与图片原子落盘。缓存键包含来源 SHA-256 与配置哈希，复用前还会检查每张帧的存在性、大小和 SHA-256。对内容模型只传递探测尺寸、覆盖范围、切点统计、启发式节奏与未来可能存在的有限 OCR 文本白名单，不传路径、URL、哈希、任务号或帧明细。

### 4.6 内容生成（app/services/content_generation.py）

DeepSeek 适配器负责把字幕文本 + 商品资料转为结构化报告。`analysis_mode=quick` 只请求一句话结论、内容结构、有效原因、可借鉴方法（可单独配置模型与 30 秒超时）；`analysis_mode=full` 生成完整脚本、拍摄表、发布内容包（90 秒超时）。密钥未配置时保留本地研究稿结构并显示 provider 未配置；调用失败降级为证据受限研究稿，且 `publishable=false` 不变。报告主要字段：`delivery`、`recommended_script`（唯一推荐稿，不给多版拼接）、`shooting_table`、`publishing_package`、`localization`、`product_requirements`、`evidence_and_risk`、`asr`。

### 4.7 商品属性分流（app/services/product_relevance.py）

结构化 `product_relevance` 统一返回 `has_product | no_product | needs_confirmation`，附置信度、判断依据、原因、后续动作和用户确认覆盖。判定优先级：用户已提交的商品资料和明确确认 > 完整模型结果 > 规则初判。资料缺口分三层：`blocking_for_interpretation`（当前解读必需）、`optional_enhancements`（可选增强）、`product_for_rewrite_or_publish`（仅商品改写或正式发布时参与门槛）。无商品内容不返回也不展示商品字段缺失项；模型完成解读后清除旧的"内容蒸馏缺失"提示。

### 4.8 前端通关路径状态机（static/app.js）

结果区按用户决策顺序组织为四关：**读懂链接 → 拆出原创稿 → 拍出来 → 把关发布**。每关状态为 `locked / active / pending / cleared / blocked`，由后端 `status`、报告字段与发布门禁共同推导：`publishable=false` 时第 4 关显示"待补充"，通关进度保持 3/4，复制动作文案保持"复制研究稿"。数字依据默认折叠，展开后只显示通俗的资料来源与采集时间；任务号、接口路径、文件哈希与模型调用元数据只保留在接口 `diagnostics` 中，前端做反向禁显验收。

## 5. 证据体系与发布前审核

证据体系的目标是"结论可追溯、状态不夸大"：

- **精简清单（evidence_manifest.json）**：真实样本约 5 KB，包含来源、稳定作品 ID、字幕语言、分段计数、缺失项和 5 个带 SHA-256 的白名单产物。`context_policy.raw_artifacts_included=false`——原始媒体不默认进入分析上下文，只有核对具体证据时才通过 `GET .../artifacts/{artifact_name}` 定向读取白名单文件。
- **元数据脱敏**：抖音元数据只保留公开字段，作品地址规范化为无查询参数的标准 URL；不保存 Provider 完整响应、媒体签名地址、`share_sign`、`did/iid`、Cookie 或请求头。
- **发布前审核门禁**（用户可见术语为"发布前审核"，API 兼容字段为 `risk_gate`）：以下情况强制 `publishable=false`，只能产出研究稿——商品名称/品类/核心卖点/规格/批准表述/证明材料缺失；用户本次补充了尚未复核的商品资料；只有字幕没有实时指标、评论原文或完整来源证据；模型生成成功但商品事实和人工审核未完成。模型生成成功不能改变发布门禁。

## 6. 发布校准闭环（P3-01）

独立自包含页面 `static/publish.html`（`/static/publish.html`），方法复用项目019：把每次已发布内容登记为可复盘实验。

状态机：`predicted → published → measured → reviewed`。

1. **登记 + 盲预测**：7 维透明打分（问题强度、受众匹配、首屏钩子、具体证据、表达清晰、可传播性、执行成本，各 1–5 分），并对曝光、播放、点赞、评论、分享、涨粉和留存率给出 T+72h 区间；必须在发布前提交，避免事后修正。
2. **发布登记**：记录平台、实际发布时间与公开链接，内容快照 SHA-256 保持不可变。
3. **回填实测**：只能按创建时冻结的 72 小时窗口回填；计数必须为非负整数，留存率为 0–100%。
4. **复盘**：区分预测偏乐观、命中区间和偏保守，产出下一轮单变量实验假设，并标记可沉淀经验候选（不自动晋升项目017，需人工确认）。

当前状态保存在 SQLite `var/publish_calibration/calibration.sqlite3`，启用 WAL、`synchronous=FULL` 与显式事务；每一步另追加到 `experiment_events`，数据库触发器拒绝事件更新和删除。旧 `ledger.jsonl` 若存在只在首次打开时只读迁移，原文件不改名、不覆盖、不删除。跨实验校准摘要仅统计已复盘事件，少于 3 条有效样本时明确 `evidence_insufficient=true`；系统不会自动训练模型，也不把相关性写成因果结论。

## 7. 数据流向与存储

```
用户浏览器
  │ 链接 /（降级）字幕文本 / ≤25MB 媒体 / 商品资料
  ▼
FastAPI 主进程（内存中处理，不持久化请求体）
  │
  ├── var/acquisition/acq_*/request.json      # 任务请求
  ├── var/acquisition/acq_*/status.json       # 状态机与进度
  ├── var/acquisition/acq_*/evidence_manifest.json  # 精简证据清单
  ├── var/acquisition/acq_*/raw/              # 白名单原始产物(媒体/音轨/字幕/元数据)
  ├── var/acquisition/acq_*/visual_analysis/  # 代表帧与结构报告（派生产物）
  ├── var/acquisition/cache/                  # completed 任务缓存(按规范化链接+参数)
  ├── var/publish_calibration/calibration.sqlite3 # 发布校准当前状态+追加事件
  └── .cache/faster-whisper/                  # 模型缓存(G 盘)
```

- 分析输入 = 精简清单 + Worker 字幕 + 公开指标；原始证据默认隔离。
- 上传转写的媒体只在本次请求中处理，响应 `source.retained=false`；外部 provider 被选中时媒体会发送到第三方服务（部署前需补充隐私说明与人工确认）。
- 仓库边界：Git 只纳入源码、测试、入口和文档，排除凭据、模型、虚拟环境、缓存、运行任务、真实媒体、素材与生成产物。

自动化集成无需逐接口调用，可用单命令入口：`.venv\Scripts\python.exe -m app.acquisition_cli --url <链接> --item-limit 1`，等待终态后只输出一条精简 JSON；超时后 Worker 继续后台运行，可按 `job_id` 查询。

## 9. 性能实现与实测基线

- **本地 ASR（RTX 4060 Ti, cuda/int8_float16）**：冷启动总计 7.88 s；热启动模型加载 0.000 s、总计 3.576 s（62 字符 2 段）。35 秒抖音视频 238 字符 5 段；255 秒分离流视频 1,652 字符 149 段；27 分钟长视频（264 MB）10,851 字符 1,185 段，全部完成且无 CPU 回退。
- **内容生成**：DeepSeek 完整解读 8,536 tokens、耗时 20.38 s，产出 267 字研究稿 + 10 段拍摄表 + 发布内容包。
- **缓存**：同一来源与参数二次提交直接命中 completed 任务；跨短链按稳定作品号复用完成缓存。
- **结果页分层**：quick 模式短输出优先返回，避免用户等待完整交付物。
- **证据清单**：真实样本精简清单 5,030 字节，控制上下文体积。
- **画面结构**：真实已有任务 9.567 秒全覆盖，生成 12 张 576×1024 JPEG；候选切点 0、估算 1 个片段、启发式慢节奏，OCR 明确 unavailable。
- **当前回归基线**：零付费 Python 全量 99/99；主页 26/26、发布校准页 30/30、画面结果页 13/13。三组当前浏览器验收在桌面与 390px 下的控制台、页面、失败请求、4xx/5xx 和横向溢出均为 0；91/91、92/92、175/175 为此前对应阶段的历史基线。

## 10. 安全设计

- **网络边界**：服务只监听 `127.0.0.1`（演示 8792 / 开发 8787），不暴露局域网；正式部署需反向代理 + HTTPS + 访问控制。
- **凭据管理**：密钥只放在服务端环境变量（`DEEPSEEK_API_KEY` / `PROJECT024_*` 系列），不进入前端、源码、Git 或日志；错误信息经 `_SECRET_PATTERNS` 正则脱敏（Bearer、sk/rk/pk 前缀、api_key/token/secret 键值、URL 查询参数）后才返回。
- **无登录态原则**：不读取 Cookie、密码、浏览器本地存储或个人登录态；隔离浏览器使用无登录临时上下文；不自动发布内容。
- **元数据最小化**：白名单字段收敛，签名 URL 与请求头不入盘；`canonical_url` 去除签名查询参数。
- **资源防护**：上传 25 MB + 扩展名/媒体类型/空文件三重校验；下载和画面分析均有 512 MiB 上限；画面分析外部命令共享 90 秒总截止时间；原子写防半写文件。
- **信息分层**：`generation`/`acquisition` 技术元数据与甲方 `report`/`source` 分离，只进 `diagnostics`；前端未知英文键默认不渲染，并通过反向禁显验收（页面不得出现 Token、`json_object`、采集任务号、内部 API 路径、64 位哈希）。
- **DLL 隔离**：CUDA 运行库只加入当前进程搜索路径，不修改系统 PATH。

## 12. 边界与已知限制

- 抖音公共 Provider `douyin.wtf` 非官方 SLA 接口，限流或失效时依赖隔离浏览器回退；两者都失败才返回 `needs_input`。平台页面/签名/CDN 变化可能要求更新探测器（保留可替换适配层）。
- 隔离浏览器回退已在 35 s 合并流与 255 s 分离流真实验证；分段媒体、不同地区页面与更多编码组合仍需抽样。超过 512 MiB 安全阻断。
- 代表帧与候选镜头结构已接入；画面文字 OCR、公开评论、主页多作品和手机端真实访问仍为后续任务。候选切点与节奏是机器启发式证据，不能替代画面语义理解。
- 只读到字幕、代表帧或切点统计都不能证明画面对象和画面文字；`needs_confirmation` 的商品判定允许用户明确确认后修正。
- 手机端局域网访问延期；正式历史管理、账号、计费、云部署属于交付前配套。
- 项目内仍有 v0.2 历史交付目录待归档（P2-02），当前唯一启动入口为 v0.3；外部备份可回滚代码但不是第二运行版本。
- 当前电脑演示默认调用 DeepSeek 产生费用，可用 `-DisablePaidContent` 切换零付费。
