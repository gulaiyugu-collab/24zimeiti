# Web 应用 v0.2 变更与决策

## 文档用途

记录项目024从轻量演示版 v0.1 进入可持续完善的 Web 开发版 v0.2 后，已经确认的产品决策、代码能力、验证边界和后续工作。本文描述开发状态，不代表甲方交付验收。

## 本轮目标

把“输入链接后返回泛化报告”的演示结构，调整为面向商品短视频生产的结果优先工作台：先给唯一推荐研究稿，再给可执行拍摄表，最后展示证据、判断与风险。

用户已确认：

1. 产品形态继续做 Web 应用 v0.2，不在当前阶段封装甲方交付版。
2. 地区/国家本地化暂不启用，但保留未来交互和请求字段。
3. 资料不完整时允许生成研究稿，但禁止标记为可发布。
4. 语音转写生产环境优先考虑外部 API，本地 ASR 作为可选回退；最终 provider 需以真实样本效果决定。
5. DeepSeek 可用于转写后的内容分析与结构化生成，不承担语音转写。

## v0.2 已实现

### 平台边界

- 抖音、TikTok 在 `/api/platforms` 中标记为 `active`。
- 抖音保留登记样本与用户补充字幕的证据降级流程。
- TikTok 增加独立适配器，可识别提交链接、解析显式视频 ID、匹配登记样本和短链 alias。
- TikTok 适配器不负责实时页面抓取、短链网络解析或媒体下载；提交 URL 不会被描述为已取得视频内容。
- YouTube、Facebook、X 继续保持 `planned`。

### 结果优先结构

报告 schema 升级为 `0.2`，新增或提升以下主字段：

- `delivery`
- `recommended_script`
- `shooting_table`
- `publishing_package`
- `localization`
- `product_requirements`
- `evidence_and_risk`
- `asr`

Web 页面按三层呈现：

1. 唯一推荐成稿。
2. 拍摄执行表。
3. 证据、判断与风险。

### 商品事实与发布前审核

请求支持自由文本 `product_context` 和结构化 `product`。结构化字段包括名称、品牌、SKU、品类、卖点、规格、随盒物品、目标受众、批准表述和证明材料 URL。

缺少商品名称或 SKU、品类、核心卖点、规格、批准表述、证明材料时，`product_requirements` 会列出缺失项。用户提交内容被标记为“未核验用户资料”，不能直接升级为已确认事实。

以下强制规则已进入后端和前端结果表达：

- 研究稿 `publishable=false`。
- 用户本次补充未复核商品资料时，不沿用登记样本中的可发布状态。
- DeepSeek 生成成功后仍强制研究稿状态。
- 发布前必须补齐商品事实、证明材料并完成人工审核。

### 地区/国家预留

请求模型已增加 `market.region`、`market.country`、`market.language`。v0.2 只保留字段和 UI 位置，不据此改写内容；响应固定表达 `future_disabled`、`enabled=false`、`applied=false`。

### 语音转写

已增加 `POST /api/transcribe`：

- 仅接受 `multipart/form-data`。
- 单文件最大 25 MB，并限制 multipart 额外开销。
- 校验媒体扩展名、MIME 类型、空文件、provider 和 language。
- 返回 transcript、provider、model、language、segments、来源哈希和执行状态。
- 上传媒体不长期保留，响应标记 `retained=false`。

ASR 路由支持 `auto`、`external`、`local`、`disabled`：

- `external` 是通用 OpenAI-compatible `/audio/transcriptions` 客户端。
- `local` 是可选 `faster-whisper` provider，按需加载。
- `auto` 按外部 API、本地 provider 的配置可用性选择。

`auto` 在外部 provider 执行失败且本地 provider 可用时允许运行时回退；显式选择 `external` 或 `local` 时不会越权切换。响应会分别记录首次选择和最终执行的 provider。

Web 页面已经提供媒体选择、大小校验、转写状态和字幕框回填。转写不会自动覆盖已有字幕，也不会自动开始分析；用户保留核对和继续操作的确认点。

### DeepSeek 内容生成

已增加服务端 DeepSeek provider，输入限定为已有字幕、自由文本商品背景和结构化商品资料，输出要求为严格 JSON，包括：

- 唯一完整推荐脚本。
- 拍摄执行表。
- 发布内容包。
- 事实、推断和待确认项。

DeepSeek 未配置时不调用付费 API；调用失败或返回结构无效时回到本地证据受限研究稿。无论生成成功与否，v0.2 都不会自动把研究稿标记为可发布。

## 当前验真边界

### 已有代码级证据

- 应用版本为 `0.2.0`。
- Python 编译检查、JavaScript 与浏览器脚本语法检查通过。
- 21 项后端测试通过，覆盖原有流程与 TikTok、上传、ASR、DeepSeek、发布前审核和脱敏行为。
- 真实桌面和手机 Chromium 共 36 项开发版浏览器检查通过，控制台错误、页面错误、请求失败和坏响应均为 0。
- 浏览器中的转写使用 mock 响应，没有调用真实外部或付费 API。

这些记录证明当前开发版页面与 mock provider 路径可运行，但不能证明外部服务或真实媒体转写已经可用。

### 尚未验真或尚未闭环

- 没有使用有效服务端凭据完成 DeepSeek 真实请求。
- 没有接通并实测阿里云百炼、AssemblyAI 等厂商专用 ASR 协议。
- 当前通用外部 ASR 客户端是否兼容目标供应商，需分别按官方协议验证。
- `faster-whisper` 可选依赖和模型尚未安装、下载和真实转写。
- Web 上传目前没有真实上传进度、取消、分段对照和第三方隐私确认，仍需继续完善。
- TikTok 实时短链解析、页面采集和媒体下载未进入当前适配器。
- TikTok 登记样本是否可直接返回完整报告，取决于 `tiktok_cases.json` 的实际内容。
- 真实外部 API 的网络、配额、计费、隐私和供应商专用错误路径仍未验真。

## ASR 供应商决策

当前不把单一供应商写死为最终默认：

- 中文、国内网络与中文业务场景可优先验证阿里云百炼。
- 全球多语言 TikTok 场景应保留其他外部 ASR 选项，并用真实样本比较准确率、分段、速度、成本和隐私条款。
- 本地 `faster-whisper` 用作隐私、断网或外部服务不可用时的可选能力。
- DeepSeek 不参与语音识别，只处理转写后的文本。

在中文、英文、马来语、混合语音、背景音乐、商品操作声和多人声等样本完成对比前，不标记任何供应商为全球默认。

## 凭据与安全决策

- API Key 只允许通过服务端环境变量或正式密钥管理提供。
- 不把密钥写入仓库、前端、Markdown、日志、演示报告或交付包。
- 外部 API 错误信息必须脱敏后返回。
- 发送媒体到第三方服务前，产品需要补充用户可见的确认、隐私说明和数据保留策略。
- 不读取 Cookie、密码、浏览器本地存储或个人登录态。

## 后续开发优先级

1. 用已核验公开证据完善 TikTok 登记样本，并补齐短链 alias 测试。
2. 完善上传进度、取消、分段对照和第三方隐私确认。
3. 抽象 provider-specific ASR 接口，分别接入并验证目标外部服务。
4. 建立多语言真实样本集，比较准确率、速度、成本和分段质量，再决定默认路由。
5. 在取得新凭据后完成 DeepSeek 与目标 ASR 的真实调用验收。
6. 后续再讨论账号、任务队列、部署、安全与交付包装。

## 本轮明确不做

- 不更新、覆盖或重新打包现有甲方验收包。
- 不把当前开发版标记为可交付或可发布。
- 不因代码存在 provider 就声称真实外部 API 已接通。
- 不启用地区/国家本地化生成。
- 不自动发布内容，不接管平台账号。
