# 采集上下文隔离 v0.2.1 完善说明

## 本次目标

把采集过程从编排 Agent 的逐步对话中移出，避免浏览器、下载、转写、OCR、重试和原始日志挤占内容分析上下文。

## 完善前后对比

| 维度 | 完善前 | 完善后 |
|---|---|---|
| 执行方式 | Agent 在当前对话里逐条运行命令 | API 或 CLI 提交任务，独立 Python 子进程执行 |
| 状态 | 依赖对话中的进度描述 | `queued`、`processing`、`completed`、`needs_input`、`failed` 持久化到 `status.json` |
| 原始证据 | 工具输出和分析材料容易混在一起 | 原始证据写入 `raw/`，默认不进入分析上下文 |
| 分析输入 | 需要从大量输出中人工整理 | 默认只读取受限字段和长度的 `evidence_manifest.json` |
| 日志 | 命令输出直接占用当前对话 | Worker 标准输出和错误保存在任务目录 |
| 缓存 | 相同链接可能重复采集 | 完成任务按规范化链接、条目数和契约版本复用 |
| 证据读取 | 可能一次读取全部文件 | 原始证据按任务白名单文件名定向读取 |
| 未完成状态 | 容易把已有链接或下载中状态说成完成 | 只有 `completed` 可进入缓存；其他状态保留证据边界 |
| Codex 入口 | 多轮命令和多轮输出 | `python -m app.acquisition_cli` 只打印一条最终 JSON |

## 新增能力

- `POST /api/acquisition/jobs`：创建隔离采集任务。
- `GET /api/acquisition/jobs/{job_id}`：读取精简状态。
- `GET /api/acquisition/jobs/{job_id}/manifest`：读取默认分析清单。
- `GET /api/acquisition/jobs/{job_id}/artifacts/{artifact_name}`：按需读取白名单原始证据。
- `python -m app.acquisition_cli`：供 Codex 或本地自动化单命令提交、轮询和返回精简结果。
- `PROJECT024_ACQUISITION_ROOT`：配置任务、缓存和证据根目录。

## 仍未完成的能力

本次完成的是“上下文隔离与任务基础设施”，不是实时平台采集器本身。以下能力仍未接入：

- 抖音/TikTok 实时公开页面抓取。
- 主页作品列表和前 N 条作品采集。
- 媒体下载、评论采集和自动转写流水线。
- 分布式任务队列、Worker 并发上限、超时终止、任务保留期和自动清理。

因此，登记样本可以进入 `completed`；未知真实链接会保留为 `needs_input`，不能声称实时采集已完成。
