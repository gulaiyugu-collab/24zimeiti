# 项目024产品定位与产品路线

## 当前阶段定位

项目024“自媒体通关搭档”当前先做手机端云端最小闭环，用小范围朋友内测验证真实需求、使用频率、留存、处理成本和最需要改进的环节。内测不是大规模公开上线，也不是把当前电脑演示直接暴露到公网。

近期内测采用云端处理，参与者通过手机浏览器使用，只授予使用权，不交付源码、内部 Agent 协议、Skill、模型凭据或可转售的完整产品副本。当前 Windows 本机 Web 应用继续作为研发、算法验证和运营诊断环境。

安装包是内测验证后的后续商业化方向：面向有电脑的客户提供 Windows 安装包；本地处理能力优先，弱设备可选受控云端处理；没有电脑的客户使用云端轻客户端。三种交付方式共用一套能力内核，不同时维护多个互相漂移的产品。

项目源码、内部 Agent 协议、Skill、模型密钥和诊断能力不随安装包或内测账号交付。客户购买的是明确范围内的使用权、更新权和约定的服务支持。

产品使用一套能力内核，提供两种体验：

- **创作陪跑**：面向希望持续创作、获得灵感与反馈的用户。
- **安心交付**：面向年长用户、小微企业和非技术用户，默认少术语、按步骤完成。

两种体验共用数据、接口、证据和发布审核，不拆成两个产品。

## 手机端 MVP 用户路径

```text
受邀用户注册或登录
→ 手机粘贴公开链接
→ 云端自动获取与理解内容
→ 查看一句话结论和原创稿
→ 查看拍摄步骤与发布前检查
→ 主动反馈问题和改进建议
```

MVP 先收敛到手机上最容易验证价值的公开单链接路径。采集、字幕、转写和画面分析尽量自动完成；手工字幕、媒体上传和 CSV/XLSX 先保留为明确标注的故障兜底，不把后台账号连接、自动发布和主页多作品采集塞入第一轮内测。

内测必须记录：任务是否完成、处理耗时、失败原因、用户是否看懂结果、是否愿意再次使用、哪些环节需要人工介入，以及每次任务的真实云端成本。朋友反馈需要区分“功能缺陷”“表达不清”“没有需求”和“外部平台限制”，不能只按主观意见改界面。

## 账号数据连接

当前本机浏览器助手可以在用户主动操作后打开登录窗口并尝试导出数据，但它依赖用户电脑上的浏览器，不能直接作为云服务器方案。

账号数据连接按以下顺序推进：

1. 官方 OAuth 和官方数据接口，具备资质时优先。
2. 官方能力不足时，评估经过安全审计的用户侧连接器；连接器只传必要的标准化数据，不上传浏览器 profile、Cookie 或密码。
3. 在 MVP 阶段先使用公开数据和用户主动导出的 CSV/XLSX；本地同步助手或客户自有存储作为后续非官方补充，不把 Cookie、密码或浏览器 profile 交给服务器。

任何方案都必须真实显示连接、授权、同步、失效、重连和撤销状态。验证码、平台审核、主体资质和接口权限属于外部边界，不能用模拟成功替代。

## 商业与权益边界

手机端朋友内测阶段只授予使用权，不默认收费、不交付源码、不承诺永久使用，不允许转售、转授权或把内测账号交给他人。内测协议需要说明数据处理范围、反馈用途、服务可能中断、模型生成结果需人工复核，以及正式商业版本与内测版可能不同。

安装包商业化阶段再验证以下组合，不能在没有真实成本数据前拍板唯一收费方式：

- 按量：按有效分析、长视频处理或模型生成消耗额度。
- 套餐：按月包含固定额度，超出后停止或单独确认。
- 组合：基础套餐覆盖常用能力，高成本任务单独按量。

拍板前必须先取得真实数据：每类任务的采集时间、CPU/GPU、模型 Token、存储、带宽、失败重试和人工支持成本。Token 数只是用量证据之一，不能直接冒充用户最终金额。

所有付费动作必须具备明确确认、余额或额度、单次上限、周期上限、幂等扣费、失败回滚、退款和对账边界。

## MVP 必须具备

1. 手机可访问的 HTTPS 入口和受邀账号。
2. 最小账号隔离，用户只能看到自己的任务和结果。
3. 可恢复的云端任务状态：排队、处理中、成功、失败和重试边界。
4. 正式生成前的明确确认、单次成本记录和异常告警。
5. 临时媒体的保存期限、自动清理、备份和删除路径。
6. 真实手机完成“登录 → 提交链接 → 查看结果 → 反馈”的验收。
7. 内测数据看板：活跃用户、任务完成率、重复使用率、失败率、平均耗时、单位任务成本和反馈分类。

## 后续规模化与安装包必备能力

1. Web、API、异步 Worker 和外部任务队列。
2. 用户账号、会话、租户数据隔离和权限审计。
3. 用量计量、费用确认、配额与成本告警。
4. 官方 OAuth 或用户侧安全连接器。
5. 对象存储、数据库备份、恢复演练和数据保留期。
6. 域名、HTTPS、反向代理、限流、错误追踪和服务监控。
7. 桌面与真实手机的完整用户路径验收。
8. 安装包代码签名、授权文件签名、设备迁移、离线宽限期、更新包签名和源码/密钥隔离。
9. 本地版、混合版和云端版的授权、远程额度、客户自有 API Key 与售后责任边界。

## 当前执行顺序

当前本机能力链路继续作为手机云端 MVP 的研发与验真基线，不把“甲方演示版”作为对外产品。近期顺序为：

1. 收敛手机端 MVP 的唯一用户路径和内测范围。
2. 完成受邀账号、HTTPS、最小租户隔离和云端任务状态。
3. 用朋友内测验证价值、留存、失败场景、成本和表达方式。
4. 根据真实数据决定继续云端、增加安装包，还是同时提供混合版。
5. 再补齐规模化队列、用量计量、自动账号连接、安装包授权和生产运维。

更多粉丝样本、官方 OAuth、自动发布和完整安装包按内测结果推进；不因追求功能完整而跳过最小闭环验证。
