1系统定位与总体架构

Windows 本机 Web 应用：用户提交公开抖音 / TikTok 单作品链接，系统完成媒体采集、字幕提取或本地转写、结构化研究稿生成，并保留证据链与发布前审核边界。

前端层  index.html + app.js（工作台）
        publish.html + publish.js（发布校准）
API 层   FastAPI 单进程，监听 127.0.0.1:8792
服务层   acquisition / douyin_media / tiktok_media
        asr / content_generation / product_relevance
        visual_analysis / publish_calibration
执行层   独立 Python 子进程 Worker（隔离采集+ASR）
        Node.js playwright-core（浏览器回退探测）
存储层   var/acquisition/{job}/ + SQLite 校准库
  • 主进程不执行采集：API 只入队返回 job_id，采集在子进程完成，Worker 日志不进入默认响应。
  • 状态即文件：request.json / status.json / evidence_manifest.json / raw/ 全部落盘，可恢复。
  • 单机单实例：多实例部署需外部队列、并发限制与清理策略（Docker 基础镜像已备）。

1这是一个什么工具

你给它一条公开视频链接，它把能验证的字幕、公开数字和画面结构线索整理出来，再据此给你写一版研究稿。

它像一位“内容研究员助理”：先梳理字幕和结构证据，再提出“为什么可能有效、哪些方法值得测试”的有边界假设；需要时还能生成新脚本、拍摄清单和发布用标题正文。

页面像闯关游戏，每条链接要过四关：

  1. 读懂链接——梳理当前能验证的内容和结构线索；
  2. 拆出原创稿——写出你的新脚本；
  3. 拍出来——给你照着执行的拍摄清单；
  4. 把关发布——检查现有资料和规则缺口，最终仍由你确认。

四关全亮才算"通关"；没过关的显示"待补充"，绝不假装完成。

2它由哪些部分组成

把它想象成一家小型工作室，四位"员工"各司其职：

"员工"干什么类比
跑腿员把你给的视频"借"回来研究替你去图书馆借书
速记员把视频里的话逐句记下来，标时间点会议记录员
研究员根据证据提出可验证假设侦探整理线索
质检员发布前最后把关工厂出厂检验员

程序、字幕听写、抽帧和记录在你自己的电脑上运行；获取公开视频会访问平台或公共采集通道，启用 DeepSeek 时还会把必要文字证据发给外部服务。工具不读取账号、密码、Cookie 或浏览器私人资料。

3主链路流程：从链接到研究稿

POST /api/acquisition/jobs  → 入队，子进程 Worker 执行
  状态机: queued → processing → completed|needs_input|failed
  1 平台适配 + URL 规范化 + 作品号提取
  2 TikTok: 代理预检 → yt-dlp 元数据 → 平台字幕优先
    无字幕 → 音轨 → 本地 faster-whisper
  2 抖音: 公共 Provider → 失效则隔离浏览器回退
    分离音视频流按 Content-Range 选完整候选并合并
  3 媒体流强制校验(视频流+音频流齐才进 ASR)
  4 GPU 转写: large-v3-turbo 带时间码分段
  5 精简证据清单(白名单字段 + SHA-256)
  6 completed 任务写缓存
前端轮询至终态 → POST .../analyze
  拒绝非 completed/空字幕/无哈希/客户端 transcript 覆盖
  已校验视频 → 本机代表帧+候选镜头结构（OCR 未安装则 unavailable）
  精简清单 + 字幕 + 公开指标 + 收敛画面证据 → DeepSeek

三个降级入口：手动字幕（POST /api/analyze，产出 partial 研究稿）、25 MB 媒体上传转写（POST /api/transcribe）、登记样本 fixture（标注 registered_fixture 来源）。

3从贴链接到出结果

全程自动，你只需粘贴链接、点"开始"：

  1. 借视频：跑腿员先走"正门"；正门关了自动换"侧门"。两条路都不通时如实告诉你"这次取不到"，绝不拿假内容糊弄。
  2. 记台词：有字幕直接用；没字幕就把声音交给"AI 速记员"听写成带时间点的文字稿。
  3. 看节奏：抽最多 12 张真实代表帧，估算可能的镜头切换；不假装认识物体或画面文字。
  4. 做分析：先给快速版结论，想要更多再展开完整报告。
  5. 出成果：新脚本、拍摄清单、发布用标题正文。

同一个链接提交第二次，直接用上次的结果——像买过的东西放进了冰箱，不用再出门买。自动流程万一失败，还有备用入口：手动粘贴字幕或上传小段视频，不会把你卡死。

4模块设计与交互

平台适配器（adapters/）

detect_platform / canonical_url / extract_aweme_id：URL 判平台、规范化去参（作缓存键）、提取稳定作品号；短链过期可从本机登记元数据恢复。YouTube/Facebook/X 已定义契约，状态 planned。

采集任务管理（acquisition.py）

任务 ID acq_时间戳_hex12 正则校验；只有 completed 进缓存，needs_input 绝不伪装；JSON 原子写（临时文件 + os.replace）。

双通道采集

抖音 Provider 优先 → 隔离浏览器回退（douyin_browser_probe.cjs，无登录态，按 media-video/media-audio 区分流）。签名地址只存在 Worker 内存。512 MiB 下载上限；TikTok 代理只检测不修改。

画面结构 / ASR / 内容生成

visual_analysis 只读清单内已校验视频：前 1200 秒、5fps scene score、最多 12 帧、512 MiB、90 秒总截止；切点与节奏仅为启发式，OCR 未安装时明确 unavailable。auto ASR = 外部→本地单选；采集 Worker 固定本地 ASR。DeepSeek 失败时降级为证据受限研究稿，publishable=false 不变。

商品分流 / 前端状态机

product_relevance：用户确认 > 模型结果 > 规则初判；缺口分 blocking_for_interpretation / optional_enhancements / product_for_rewrite_or_publish 三层。前端四关状态 locked/active/pending/cleared/blocked 由后端状态与发布门禁共同推导。

4每个功能是怎么设计的

两层结果，像先上小菜再上正餐

第一层"快速看懂"：一句话结论、内容结构、有效原因、可借鉴方法；第二层"完整交付"：脚本、拍摄清单、发布内容包，需要时再展开。

唯一推荐稿，不让你做拼图

只给一版主稿，拿到手就能用。

拍摄清单像菜谱

什么时间、拍什么画面、说什么口播、写什么字幕、商品证明放哪，一行行列清楚，照着拍就行。

真实代表帧与机器估算分开说

页面会展示真正抽出的画面，并把候选镜头节奏标成“机器估算”；没有 OCR 时直接写明，绝不拿切点数量冒充看懂画面。

先问"是不是卖货内容"

是商品内容→告诉你补哪些商品资料；不是→走普通分析不来烦你；拿不准→显示"待确认"，你一键告诉它是或不是，你的判断永远优先。

数字旁边都有"查看依据"

像超市小票——可以不看，但必须给你留着。

5证据体系与发布前审核

  • 精简清单：真实样本约 5 KB，含来源、稳定 ID、字幕分段与 5 个带 SHA-256 的白名单产物；raw_artifacts_included=false，原始媒体默认不进分析上下文，核对时按白名单定向读取。
  • 元数据脱敏：只保留公开字段，URL 规范化去签名参数；不保存 Provider 完整响应、签名地址、share_sign、did/iid、Cookie、请求头。
  • 发布前审核门禁（API 兼容字段 risk_gate）：商品资料缺失 / 未复核 / 只有字幕无实时指标与完整证据 / 人工审核未完成 → 强制 publishable=false，只能产出研究稿。模型生成成功不能改变门禁。

5为什么它"说话有据"，不让你乱发

这个工具最重要的性格：宁可少说，绝不乱说。

  • 稿子分两种身份——"研究稿"和"可发布稿"。资料不全只给研究稿，并标注"不能直接发布"——菜没熟绝不端上桌。
  • 要升级成可发布稿，得补齐商品资料、证据和人工确认，谁也不能跳过，AI 自己生成的内容也不例外。
  • 发布前把关检查：商品信息全不全、有没有夸大或违规的说法（如保健品不能乱承诺功效）、证据够不够。
  • 从不承诺"发出去一定火"。

对你意味着：看到“待补充”就先补资料；“已通关”只表示程序内检查项已满足，正式发布仍由你人工确认，也不代表平台审核或法律意见。

6发布校准闭环（P3-01）

自包含页面 static/publish.html，方法复用项目019。状态机 predicted → published → measured → reviewed：

  1. 登记+盲预测：7 维打分 + 曝光、播放、点赞、评论、分享、涨粉、留存率的 T+72h 区间，发布前必须提交。
  2. 发布登记 → 同窗口回填 → 复盘：区分偏乐观/命中/偏保守，只给下一轮单变量实验假设。

SQLite WAL 保存当前状态，不可更新/删除的事件表追加历史；旧 JSONL 只读迁移且不修改源文件。有效复盘少于 3 条时明确证据不足，不输出确定性流量承诺。

6积累校准证据，不假装自动变准

独立页面"发布校准"，像错题本 + 存折的组合：

  1. 发布前先“押题”：七项打分，并写下发布后 72 小时的七项指标区间。
  2. 发布后“对答案”：满同一 72 小时窗口后填真实数据。
  3. 计算偏差：告诉你偏乐观、命中还是偏保守，给下一轮单变量实验建议。

它帮你积累证据，但不会自动训练或保证越来越准。少于 3 条有效复盘时明确写“证据不足”；建议始终是待验证假设，只有你确认过才沉淀。

7你的资料都去哪了

三句话讲清白：

  1. 本机处理和保存。采集产物、字幕、代表帧和实验记录在本机；获取公开内容和可选 DeepSeek 生成仍会访问外部服务。
  2. 只看公开内容。只处理你主动给的公开视频链接，不碰账号密码，不看你任何平台的登录信息，也绝不自动替你发内容。
  3. 原始视频受控保存。默认分析只读精简清单；完整媒体、字幕和代表帧位于任务独立目录，程序按白名单定向读取。

唯一例外：配置了付费 AI 服务时，生成稿子会调用外部服务并产生少量费用；不想用，启动时选"零付费模式"。

9性能实现与实测基线

  • 本地 ASR（cuda/int8_float16）：冷启动 7.88 s；热启动总计 3.576 s。35 s 视频 238 字符 5 段；255 s 分离流 1,652 字符 149 段；27 分钟（264 MB）10,851 字符 1,185 段，无 CPU 回退。
  • DeepSeek 完整解读：8,536 tokens、20.38 s，267 字研究稿 + 10 段拍摄表。
  • 缓存：同链接+参数二次提交直接命中；跨短链按稳定作品号复用。
  • 分层结果：quick 短输出优先返回。
  • 画面结构：真实任务覆盖 9.567 秒，12 张 576×1024 JPEG，OCR unavailable。
  • 当前回归：Python 99/99；主页 26/26、发布页 30/30、画面页 13/13；控制台/请求/溢出均为 0。

9速度与稳定

  • 短视频：从提交到出结果，通常几十秒到一两分钟。
  • 听写很快：半分钟的视频几秒钟记完；27 分钟长视频也能完整处理。
  • 重复提交同一链接：直接出上次结果，几乎瞬间。
  • 网络小波动不娇气：正门关了自动换侧门；TikTok 需要的网络环境没开会明确提示，而不是莫名其妙报错。
  • 速度的底气来自你自己的电脑：有独立显卡，听写就在显卡上飞快完成，不花一分钱。

10安全设计

  • 网络边界：只监听 127.0.0.1；正式部署需反代 + HTTPS + 访问控制。
  • 凭据管理：密钥只在服务端环境变量；错误信息经正则脱敏（Bearer/sk-rk-pk/api_key/token/secret/URL 参数）。
  • 无登录态：不读 Cookie、密码、本地存储；隔离浏览器无登录上下文；不自动发布。
  • 元数据最小化 + 资源防护（25 MB 上传 / 512 MiB 下载和画面分析上限 / 画面分析 90 秒总截止 / 原子写）。
  • 信息分层：技术元数据只进 diagnostics；前端反向禁显验收（不得出现 Token、json_object、任务号、内部路径、64 位哈希）。
  • DLL 隔离：CUDA 库不改系统 PATH。

10安全与隐私

  • 不碰账号：不需要登录任何平台，不存密码。
  • 不偷看：不读你浏览器里的任何私人数据。
  • 不乱发：发布按钮永远在你自己手里。
  • 钥匙锁好：付费服务密钥只存在你电脑的配置里，不进页面、文档或记录。
  • 有界限：超大的视频文件会明确拒绝，防止撑爆硬盘。
  • 只管本机：外面的人访问不到。

  • Docker：docker build -t self-media-growth-partner .（生产配套见第 1 章）。

11怎么装、怎么开

如果在这台已装好的电脑上用，什么都不用装。日常两步：

  1. 双击桌面快捷方式（或项目根目录"项目024_v0.3_甲方演示.cmd"）；
  2. 浏览器打开本地页面（127.0.0.1:8792 开头，只属于你的电脑），粘贴链接开用。

小贴士：重复双击不会开第二个；分析 TikTok 前先开网络工具（VPN）；想零成本就带"零付费模式"启动。换新电脑安装时，请懂技术的同事照技术版第 11 章操作。

12边界与已知限制

  • douyin.wtf 非官方 SLA；限流/失效依赖隔离浏览器回退，双失败才 needs_input；平台变化可能要求更新探测器（保留可替换适配层）。
  • 回退已验 35 s 合并与 255 s 分离流；分段媒体/地区页面/更多编码仍需抽样；超 512 MiB 阻断。
  • 代表帧与候选镜头结构已接入；OCR、公开评论、主页多作品、手机端真实验收仍是后续任务。
  • 字幕、代表帧和切点统计不能替代画面语义理解；needs_confirmation 可由用户确认修正。
  • v0.2 历史交付目录待归档（P2-02）；外部备份可回滚但非第二运行版本。
  • 默认演示调用 DeepSeek 产生费用。

12现在还做不到的事

  • 只认单条视频链接：账号主页全部作品、评论区暂不支持。
  • 能抽帧、能估算剪辑点，但还不能真正看懂画面：没有 OCR，不能读画面文字，也不能仅凭切点数判断物体和动作。
  • 只支持两个平台：抖音和 TikTok；YouTube、Facebook、X 在计划中。
  • 手机上用还差点火候：目前在电脑浏览器里用。
  • 发出去不保证火：它把内容和把关做扎实，但流量没人能打包票。
  • 偶尔取不到视频：平台接口偶尔抽风，它会如实说"没取到"，重试或换链接即可。
一句话总结：这是一个住在你自己电脑里、诚实到有点较真的"自媒体研究助理"——你给它一条链接，它还你一套看得懂、用得上、有依据、能复盘的内容方案。
